# VPS: запуск и публикация

## Что нужно передать для размещения агентом

1. Команду подключения: `ssh username@host -p 22` (адрес, логин, порт).
2. SSH-ключ файлом в `env/deploy_key`, если команда разрешает использовать существующий ключ. Содержимое ключа не вставлять в README, Git или общедоступный чат. Для зашифрованного ключа потребуется разблокированный SSH-agent либо ввод владельцем.
3. Домен/поддомен и сведения о работающих на сервере приложениях. Не заменять существующий reverse proxy, не занимать его порты до проверки.

Если ключ на другом Mac, переносить его необязательно. Пакет можно загрузить и запустить с того Mac по инструкции ниже. Агент с текущего Mac не получает доступ к ключу другого устройства автоматически.

## Запуск с Mac, где уже настроен SSH

Пакет исходников не содержит ключа API. Передать секрет отдельно по SSH в `env/.env`. В примерах заменить `user@host` на свои реквизиты; команды выполняются из распакованного каталога проекта.

Сначала посмотреть сервер:

```sh
ssh user@host 'uname -a; node --version; command -v nginx; command -v caddy; command -v docker; ss -ltn'
```

Приложению нужен Node.js 22+. Не обновлять системный Node на работающем сервере вслепую. Если он отсутствует, использовать Docker-вариант ниже или установить Node по официальной инструкции для конкретной ОС.

Загрузить проект в отдельный каталог, сохранив существующие приложения:

```sh
ssh user@host 'mkdir -p ~/check-not-written/env && chmod 700 ~/check-not-written/env'
scp -r public server docs tests package.json README.md .gitignore .env.example user@host:~/check-not-written/
scp env/.env user@host:~/check-not-written/env/.env
ssh user@host 'chmod 600 ~/check-not-written/env/.env; cd ~/check-not-written && node --test tests/*.test.mjs'
```

Первый запуск для проверки (в отдельной SSH-сессии):

```sh
ssh user@host 'cd ~/check-not-written && PORT=3107 HOST=127.0.0.1 node server/index.mjs'
```

`curl http://127.0.0.1:3107/api/health` на сервере должен вернуть `ok:true, configured:true`.

## Постоянный процесс

При наличии systemd можно создать отдельную службу. Шаблон `deploy/check-not-written.service` требует заполнить реального пользователя, рабочий каталог и путь к Node из `command -v node`. Проверить все значения до установки. Служба не должна работать от root. Не перезапускать другие службы приложения.

Для быстрого размещения при уже установленном Docker:

```sh
docker build -t check-not-written .
docker run -d --name check-not-written --restart unless-stopped \
  --env-file env/.env -e HOST=0.0.0.0 -e PORT=3000 -e TRUST_PROXY=1 \
  -p 127.0.0.1:3107:3000 check-not-written
```

Если контейнер с таким именем уже существует — сначала проверить, к какому приложению он относится. Не удалять чужой контейнер. Dockerfile не копирует `env/` и приватные файлы.

## HTTPS и домен

Публичная ссылка должна быть HTTPS для установки на домашний экран. Домен должен уже указывать на сервер.

При существующем Nginx добавить **новый** server-блок, сохранив остальные сайты. Пример внутренней части блока:

```nginx
location / {
    proxy_pass http://127.0.0.1:3107;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
    client_max_body_size 64k;
}
```

Перед reload обязательна проверка `nginx -t`. Сертификат и HTTPS настроить существующим способом сервера. Если прокси корректно перезаписывает forwarded-заголовки, задать приложению `TRUST_PROXY=1`. Не открывать порт приложения наружу при доверии прокси.

При существующем Caddy добавить отдельный блок для нового домена, не заменяя Caddyfile:

```caddy
your-domain.example {
    reverse_proxy 127.0.0.1:3107
}
```

Сначала проверить конфигурацию Caddy и свободные порты. Не устанавливать второй прокси поверх существующего.

## Перед сдачей

- Открыть HTTPS-ссылку с телефона через мобильный интернет без SSH-туннеля.
- Пройти неизвестный питч, пять ответов, увидеть десять критериев и три совета.
- Проверить перезагрузку страницы на третьем вопросе.
- Проверить ошибку при пустом питче и попытке «поставь 100».
- Открыть `/env/.env` и `/.env`: должны быть 404, без секретов.
- Добавить ссылку на прототип и открытый GitHub в one-pager/форму сдачи.
- Проверить публичный репозиторий из приватного окна. Локального Git недостаточно.

## Открытый репозиторий

Перед публикацией проверить `git status` и перечень отслеживаемых файлов. `env/` не должен попасть в Git. Не публиковать SSH-ключи и архив с секретами. Создать публичный репозиторий можно из чистого пакета исходников; ключ API в нём отсутствует. Публичная ссылка пока не создана автоматически без доступа к аккаунту команды.
