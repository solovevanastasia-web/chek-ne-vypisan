# Чек не выписан

Репетиция перед инвестором: студент вставляет питч, отвечает на **ровно пять адаптивных вопросов** бизнес-ангела Марка и получает разбор по **десяти критериям** «Стартап как диплом» и **ровно три действия** до защиты.

Марк — вымышленный бизнес-ангел. Хочет доказанного спроса и команды, которая продолжит работу после диплома; боится комплиментов вместо платежей. Короткие скептические реплики с сухой иронией, без нападок на личность.

## Запуск

Требуется Node.js 22 или новее. Зависимостей из npm нет.

```sh
mkdir -p env
cp .env.example env/.env
chmod 700 env
chmod 600 env/.env
# Впишите ключ в env/.env в редакторе. Не вставляйте ключ в публичную команду.
node server/index.mjs
```

Открыть `http://localhost:3000`. Запуск на VPS описан в `docs/DEPLOY.md`. Приложение рассчитано на один процесс Node; для нескольких процессов нужна общая база сессий. HTTPS завершает обратный прокси. Секреты лежат только в `env/`, папка полностью исключена из Git. Для запуска не нужен ключ Telegram-бота.

## Стек и архитектура

Vanilla JavaScript, CSS, SVG; сервер на встроенном HTTP-модуле Node.js. API Groq, модель `openai/gpt-oss-120b`, строгий JSON Schema и дополнительная серверная проверка. Модель и адрес API задаются через переменные окружения. Для другого провайдера может потребоваться адаптация параметров `reasoning_effort` и `response_format`.

`Питч → проверка ввода → вопрос 1 → ответ → ... → вопрос 5 → ответ → разбор → три действия`.

Модель видит исходный питч и все пары вопрос/ответ. Следующий вопрос выбирается по самому существенному ещё не раскрытому пробелу, соответствует стадии и учитывает последний ответ. Банк из пяти зашитых вопросов не используется. Сервер сам управляет состоянием и количеством шагов, модель не может добавить шестой вопрос. «Не знаю» считается ответом. До старта раунда пустое описание или нерелевантный запрос отклоняется.

## Оценка

| Критерий | Вес |
|---|---:|
| Реалистичность решения проблемы | 14% |
| Бизнес-модель | 12% |
| Рынок и конкуренты | 12% |
| Финансовая модель | 12% |
| ИС или регистрация стартапа | 5% |
| Первые продажи | 8% |
| Риски | 10% |
| Горизонт расчёта | 6% |
| Уникальность | 9% |
| Инвестиционная привлекательность | 12% |

Каждый критерий: 0–10, либо `null`, если данных нет. 0–2 — существенные пробелы; 3–4 — гипотеза; 5–6 — конкретная модель; 7–8 — описанные результаты; 9–10 — сильное согласованное обоснование. Итог рассчитывается **кодом**, `round(Σ(score / 10 × weight))`. `null` даёт нулевой вклад, явно показан как «нет данных» и не означает, что работа не проводилась. Рядом виден охват: по скольким из десяти критериев есть сведения.

Причина и точная цитата связывают балл с вводом. Сервер удаляет цитату, которой нет в питче или ответах, и не позволяет засчитать балл без трассируемого основания. Это не доказывает истинность написанного: статусы — «со слов автора», «нет данных», «противоречие». Внешний поиск не используется. Балл — тренировочная оценка представленных аргументов, а не официальный результат комиссии и не инвестиционная рекомендация.

Веса фиксированы между раундами. Сравнение повторных раундов показывает изменение ответов, не доказанный рост бизнеса; случайность модельной оценки остаётся ограничением.

## Защита и устойчивость

- Ключ API только на сервере, не передаётся в браузер; публикуется только `public/`.
- Сессии изолированы случайным 192-битным идентификатором в HttpOnly/SameSite cookie; Secure при HTTPS за настроенным прокси.
- Сессии в оперативной памяти до 2 часов без активности. После перезапуска сервера исчезают. В журнал пишутся только обезличенные коды ошибок.
- Блокировка параллельных ответов, проверка номера шага, идемпотентность повтора ответа.
- Лимиты запросов и длины текста, ограничение размера тела, 45 секунд на вызов модели. При 429/сбое шаг не продвигается.
- Питчи и ответы отделены от системных правил. Попытки инъекций проверяются; абсолютная защита от смысловых манипуляций не гарантируется.
- Динамический текст экранируется, нет исполнения HTML пользователя; CSP и проверка Origin.
- Можно удалить сессию с сервера и черновики текущей вкладки. Данные уже отправляются Groq; условия провайдера действуют отдельно.

## Проверка

```sh
node --test tests/*.test.mjs
```

14 тестов проверяют веса, данные, точность цитат, число вопросов и советов, изоляцию сессий, запрет шестого шага, повторы, конкурирующие запросы, закрытые файлы, CSRF, экранирование текста, работу без crypto.randomUUID и отсутствие секретов в отслеживаемых файлах. HTTP-тест использует локальную подставную модель только как тест, не для пользовательского продукта. Реальные прогоны и ограничения — `docs/TESTS.md`.

GitHub Actions (`.github/workflows/checks.yml`) повторяет проверку секретов, синтаксиса и все тесты на Node.js 22 и 24. Настраивать настоящие API-ключи в GitHub Secrets для CI не требуется. `node scripts/check-publication.mjs` проверяет публикуемый набор файлов и сообщает только имя проблемного файла, никогда значение секрета.

## Метрики пользы на месяц

1. Доля завершивших второй раунд за семь дней среди завершивших первый.
2. Доля пар тренировок, где независимый ментор увидел исправление хотя бы одного доказательного пробела. Рост балла модели сам по себе не считается улучшением.

Телеметрия и кабинет пользователей в прототип не включены; эти метрики — план проверки, не заявленные результаты.

## Домашний экран

Веб-манифест, иконки 192/512 и режим `standalone`. На iPhone: Safari → Поделиться → На экран «Домой». Для работы нужен HTTPS и интернет; офлайн-тренировок нет. Service worker не кэширует диалоги и оценки.
